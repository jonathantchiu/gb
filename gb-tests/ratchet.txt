# Pass-rate ratchet. One line per ROM:
#   <pass|fail|not-applicable|timeout> <path under gb-tests/roms/>[@Mcycles] [# reason]
# `cargo test -p gb-tests` asserts reality matches this file exactly: a regression
# fails the build, and so does a new pass not yet recorded. A `pass` line must
# carry a ` # reason` (anti-goal: unexplained passes are bugs). `not-applicable`
# = wrong hardware revision, or needs a boot ROM that isn't in CI; it leaves the
# pass-rate denominator. `timeout` is distinct from `fail` (different causes).
# Budgets are emulated M-cycles, not wall time, so the suite is deterministic.
# Record progress with: cargo run -p gb-tests --release --bin ratchet -- --update
